ГдеСдать (Project T) ♻️

ГдеСдать — это современная эко-платформа для поиска, оценки и управления пунктами приема вторсырья. Проект представляет собой единую краудсорсинговую систему, где жители городов могут находить пункты переработки, оставлять отзывы, ставить оценки и предлагать исправления, а бизнес и модераторы — удобно управлять точками сбора.

Ссылка на проект: https://github.com/Snowdy54/project_t

🛠 Технологический стек

Основной стек:

Backend: Python 3.12+, Django 6.0.3, Django REST Framework 3.17.1

Database: PostgreSQL 15, PostGIS 3.3 (геопространственные данные)

Frontend: React 19 (Vite), Bootstrap 5.3, Yandex Maps API

DevOps: Docker, Docker Compose, WSL 2 / Linux-окружение

Стек технологий (подробнее):

Django 6.0.3              - основной веб-фреймворк бэкенда

⚡ Функциональность проекта

Для гостей:

Просмотр интерактивной карты с одобренными точками сбора.

Поиск и фильтрация пунктов по широким категориям сырья (Пластик, Металл, Стекло, Бумага и др.).

Чтение статей в базе знаний, эко-просвещение и прослушивание подкастов.

Для авторизованных пользователей:

✅ Личный кабинет: управление профилем (Имя, Город, Обо мне, Номер телефона), загрузка аватара.

✅ Безопасность: смена пароля с обязательной валидацией старого значения и каскадное удаление аккаунта (GDPR-совместимость).

✅ Добавление точек сбора: отправка пунктов с ценами, контактами, сайтом, ссылками и расписанием. Новые точки улетают на модерацию (pending) и скрыты от гостей.

✅ Социальные функции: отправка комментариев к точкам с автоматической привязкой автора и уникальная система лайков/дизлайков с защитой от накрутки (1 юзер = 1 голос).

✅ Инструмент краудсорсинга: возможность предложить исправление неактуальной информации на точке (PointEditSuggestion).

Для администратора (модератора):

Одобрение или отклонение присланных точек (перевод из pending в approved).

Просмотр и обработка жалоб и предложенных пользователями исправлений.

Управление базой цен на сырье и глобальным списком отходов в админ-панели.

🚀 Как запустить проект локально (в Docker)

Весь стек полностью настроен для развертывания в контейнерах.

Шаг 1: Клонирование репозитория

git clone https://github.com/Snowdy54/project_t.git
cd project_t


Шаг 2: Сборка и запуск контейнеров

docker-compose up -d --build


Шаг 3: Миграции и инициализация БД

# Применение миграций PostgreSQL
docker-compose exec backend python manage.py migrate

# Создание администратора
docker-compose exec backend python manage.py createsuperuser


Доступ к сервисам:

Фронтенд (React): http://localhost:5173

Бэкенд API (Django): http://localhost:8000/api/

Админка Django: http://localhost:8000/admin/

🎯 Модели Данных и Связи

User: абстрактный пользователь Django со свойствами города, телефона, аватара и статусом автора.

Point (Точка приема): ГИС-модель с координатами PointField (SRID 4326), ИНН, ИП/ООО, адресом и статусом (pending/approved).

PointWastePrice (Цены): связывает Точку и Тип отхода, задает цену, единицу измерения (unit), статус доступности.

WasteType (Виды сырья): содержит имя (name - "Ящик для фруктов") и общую категорию (description - "Пластик") для группировки цен на фронтенде.

Review (Отзывы): комментарии с оценкой, привязанные к точке и автору.

PointReaction (Лайки): уникальные лайки/дизлайки (unique_together = ('user', 'point')).

PointEditSuggestion (Предложения правок): жалобы и корректировки от пользователей.

❌ Возможные ошибки на Windows и решения

Ошибка: exposing port TCP 0.0.0.0:8000 ... bind: An attempt was made to access a socket

Причина: Порт 8000 (Django) или 5432 (Postgres) заблокирован WinNAT или Hyper-V.

Решение: Откройте PowerShell от имени Администратора и перезапустите службу winnat:

net stop winnat
# Запустите контейнеры в обычном терминале: docker-compose up -d
net start winnat


Ошибка: AssertionError: basename argument not specified...

Причина: Роутер запутался в динамическом методе get_queryset во вьюсете точек.

Решение: Добавьте basename='point' при регистрации в api/urls.py:

router.register(r'points', PointViewSet, basename='point')
